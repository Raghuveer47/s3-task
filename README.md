# Student Profile Image Upload (Amazon S3)

This is a beginner-friendly MERN example that teaches one idea:

**The browser talks to your backend. Your backend talks to Amazon S3.**

The React frontend never uploads to S3 directly. AWS access keys stay on the Node.js server only.

## Architecture

```text
Browser
   ↓
Frontend (React)
   ↓ POST /api/upload
Backend (Node.js / Express)
   ↓ AWS SDK
Amazon S3
   ↓
profiles/
```

Uploaded objects look like:

```text
profiles/
   1727000000_student1.jpg
   1727000001_student2.png
```

The S3 bucket should stay private. The backend creates a short-lived viewing URL so the browser can display the image.

## 1. Create an S3 bucket

1. Sign in to the [AWS Management Console](https://console.aws.amazon.com/).
2. Open **Amazon S3**.
3. Click **Create bucket**.
4. Enter a globally unique bucket name, for example `student-profile-images-yourname`.
5. Choose a region close to you, for example **ap-south-1 (Mumbai)** or **us-east-1 (N. Virginia)**.
6. Keep **Block all public access** turned **ON**.
7. Click **Create bucket**.

Remember the bucket name and region. You will put both values in `.env`.

## 2. Which AWS region to select

Pick one region and use it in both places:

- the S3 bucket region in the AWS console
- `AWS_REGION` in `backend/.env`

If these two values do not match, uploads will fail.

Example:

```text
AWS_REGION=ap-south-1
```

## 3. IAM permissions the backend needs

Create an IAM user for this class project and attach a policy that allows only the actions this app uses:

- `s3:PutObject` on `arn:aws:s3:::YOUR_BUCKET_NAME/profiles/*`
- `s3:GetObject` on `arn:aws:s3:::YOUR_BUCKET_NAME/profiles/*`
- `s3:ListBucket` on `arn:aws:s3:::YOUR_BUCKET_NAME`

Example policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME",
      "Condition": {
        "StringLike": {
          "s3:prefix": ["profiles/", "profiles/*"]
        }
      }
    },
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/profiles/*"
    }
  ]
}
```

Create an access key for that IAM user. You will paste the access key ID and secret access key into `.env`.

Do **not** put these keys in frontend JavaScript.

## 4. Configure the `.env` file

```bash
cd backend
cp .env.example .env
```

Open `backend/.env` and fill in your values:

```text
PORT=5050
AWS_REGION=ap-south-1
AWS_ACCESS_KEY_ID=your_access_key_id_here
AWS_SECRET_ACCESS_KEY=your_secret_access_key_here
S3_BUCKET_NAME=your_bucket_name_here
```

Never commit `.env`. It is already listed in `.gitignore`.

## 5. Install dependencies

Backend:

```bash
cd backend
npm install
```

Frontend:

```bash
cd frontend
npm install
```

## 6. Start the backend

```bash
cd backend
npm start
```

The API should run at `http://localhost:5050`.

This project uses port `5050` because macOS often occupies port `5000`.

## 7. Start the frontend

Open a second terminal:

```bash
cd frontend
npm run dev
```

The React app should run at `http://localhost:5173`.

The Vite dev server proxies `/api` requests to the backend, so the frontend can call `/api/upload` and `/api/files`.

## 8. How to test image upload

1. Open `http://localhost:5173`.
2. Enter a student name.
3. Choose a JPEG, PNG, or WebP image smaller than 5 MB.
4. Click **Upload Image**.
5. Confirm the success message, image preview, and S3 key appear.
6. Confirm the same image appears in **View Uploaded Files**.

You can also test the API directly:

```bash
curl -X POST http://localhost:5050/api/upload \
  -F "name=Ada" \
  -F "image=@./profile.jpg"
```

```bash
curl http://localhost:5050/api/files
```

## 9. Verify the object in the S3 bucket

1. Open the AWS console.
2. Go to **Amazon S3** → your bucket.
3. Open the `profiles/` folder.
4. You should see a new object such as `1727000000_Ada.jpg`.

## API endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/api/upload` | Receive one image and upload it to S3 |
| GET | `/api/files` | List objects under `profiles/` and return viewing URLs |

`POST /api/upload` accepts `multipart/form-data` with:

- `name`: student name
- `image`: one image file (`image/jpeg`, `image/png`, or `image/webp`)

Success response:

```json
{
  "success": true,
  "message": "Image uploaded successfully",
  "file": {
    "key": "profiles/1727000000_Ada.jpg",
    "originalName": "profile.jpg",
    "contentType": "image/jpeg",
    "url": "https://..."
  }
}
```

The `url` value is a controlled, time-limited viewing link generated by the backend. The bucket itself does not need to be public.

## Common errors

| What you see | What to check |
| --- | --- |
| No file selected | Choose an image before clicking Upload |
| Unsupported file type | Use JPEG, PNG, or WebP |
| File too large | Use an image under 5 MB |
| Backend unavailable | Start the Node.js server on port 5050 |
| AWS configuration is incomplete | Fill in `backend/.env` and restart the backend |
| Could not upload / list files | Check bucket name, region, and IAM permissions |

## Security notes for students

- AWS keys belong only in `backend/.env`.
- The frontend never uses the AWS SDK.
- Keep the S3 bucket private.
- The backend creates signed URLs so images can be previewed without making the whole bucket public.
